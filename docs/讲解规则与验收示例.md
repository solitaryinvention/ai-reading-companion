# 讲解规则与验收示例

0.5.4 起，应用在每次请求中附加统一讲解规则，覆盖已有书籍和已有会话，不覆盖个人 agent.md 或授课进度。源文件为 `electron/teaching.ts`。这些是预期表现和人工验收材料，不是实际模型输出或已经通过的模型效果评测。

## 目标

让尚未读过原文的读者，仅凭本次讲解也能知道所提供材料讲了什么、关键概念指什么、前后怎样连接。先完整交代内容，再解释联系；引用负责核对依据，不代替正文。读过或讲过不代表已经理解。

五档详略都遵守这一要求。极简减少次要细节；深入补充解释和例子。仅当用户明确询问写法或结构时，才讨论作者的编排。短内容不强制分节，不机械输出教学流程标题。

## 示例一：事件经过

以下为虚构测试材料：一座城原先依靠一条河取水，连续少雨导致水位下降。居民先限制用水，随后建造蓄水池，储存雨季的水。枯水期因此有了额外水源，但蓄水池仍依赖此前积水。

请求：讲清这段内容。分别用极简、标准和深入档检查。

预期：先说明城市原来的取水方式，再交代少雨、水位下降、限水、蓄水与枯水期取水的过程。解释蓄水池改变的是水的储存时间，不是凭空增加降雨。不得编造城市名称、年代、人物或结果。

不合格：以“为什么作者先介绍河流”开头；只说“原文讲了一个资源管理故事”；未交代具体经过就拔高为文明主题。

## 示例二：概念关系

以下为虚构测试材料：某书把“存量”定义为某一时刻的总量，把“流量”定义为一段时间内的变化量。水箱里现在有多少水是存量，每分钟流入多少水是流量。流入大于流出时，箱中水量增加。

请求：我没读过原文，直接讲懂。

预期：明确解释两个词及其时间差别，结合水箱说明，再把流入、流出和积累的关系连接起来。用户不点来源链接也能复述区别。标题如需要，应概括实际内容。

不合格：先问“这个区分为什么值得专门介绍”；只写“作者作了一个重要对比”；直接使用两个术语而不解释。

## 示例三：没有原文

输入只有书名、章节目录和“已讲第一章”的进度，没有书籍摘录。请求：继续讲第二章。

预期：明确第二章正文尚未提供，请附加当前章节或粘贴原文。不得据目录编造内容，也不能把进度当作读者已掌握知识的证明。可说明已有讨论的范围。

## 示例四：明确询问写法

有完整摘录，用户请求：为什么作者把两个例子放在这个顺序？

预期：简短交代例子实际内容，然后直接回答这个结构问题，区分可见安排与解释者推测。不得把默认讲解规则变成一律拒绝问句或结构分析。

## 验收方式

- 检查人物与术语是否在需要时得到介绍、每个“这/它/上述”是否有清楚指代。
- 让没有看过材料的人复述内容与主要联系；不能用“点原文就知道”补救正文缺失。
- 在五档和两个连接通道检查实际请求携带同一讲解规则、当前用户要求不变、个性化文件不被覆盖。
- 自动化测试只验证请求、隔离与文件兼容性。真实模型的讲解质量需要另行试读，不能将模拟回答当作质量证明。
